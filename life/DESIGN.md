# 인생 시뮬레이션 기획서 (초안)

> 함께 만들어 가는 문서입니다. 결정된 것은 **확정**, 아직 정하지 않은 것은 **미정**으로 표시합니다.
> 참고한 게임: [킥루 - 벤치에서 발롱까지](https://kickru.com/) (축구선수 한 명의 커리어를 키우는 시뮬레이션). 이 게임은 같은 방식을 **한 사람의 인생 전체**로 넓힙니다.

## 1. 확정된 방향

| 항목 | 결정 |
|---|---|
| 장르 | **텍스트 기반 인생 시뮬레이션**. 사건마다 선택지를 골라 한 사람의 인생을 만들어 감 (로그라이크 요소 없음) |
| 배경 | **현대 한국** |
| 진행 | 버튼 한 번에 **1년**. 한 인생은 약 30분~1시간 |
| 끝 | **사망하면 끝**. 대를 잇거나 이어서 하지 않음 |
| 평가 | 행복·재산·명성·인간관계 등 **여러 기준을 합쳐 인생 등급**을 매김 |
| 이야기 | **섞어서**: 단계별 큰 사건은 직접 쓰고, 자잘한 사건은 규칙(문장 틀 + 조건)으로 조합 |
| AI | 처음에는 **AI 없이** 완성. 나중에 **Gemini 무료 API를 켜고 끄는 옵션**으로 추가 (아래 참고) |
| 플랫폼 | **모바일 웹** 먼저, 같은 코드를 **Android APK**로 패키징 |
| 저장 | 기기 안에 자동 저장 + 저장 파일 내보내기/가져오기 |
| 위치 | 이 저장소의 `life/` 폴더. 리듬게임과 따로 빌드 |
| 목적 | 취미 프로젝트, 큰 규모로 오래 키워 감. 스토어 출시는 목표에 넣지 않음 |
| 그래픽 | **미정** (보류) |

## 2. AI 사용 원칙

- 게임은 **AI 없이도 끝까지 플레이할 수 있어야** 합니다.
- AI 생성은 설정에서 켜는 옵션입니다. 켜면 자잘한 사건의 문장과 선택지를 Gemini 무료 API가 더 다양하게 만들어 줍니다.
- **API 키는 저장소와 APK에 넣지 않습니다.** 설정 화면에서 직접 입력하고 그 기기 안에만 저장합니다.
- 무료 한도를 넘거나 인터넷이 끊기면 **자동으로 규칙 기반 사건으로 돌아갑니다**. 게임이 멈추지 않습니다.
- AI는 문장만 만들고, **능력치 변화와 확률은 항상 게임 규칙이 정합니다**. AI가 게임 균형을 깨지 않게 하기 위해서입니다.

## 3. 핵심 흐름 (초안)

### 3-1. 시작
- 이름과 성별을 정합니다.
- 무작위로 만든 **출생 후보 3명** 중 하나를 고릅니다. 후보마다 집안 형편, 부모, 타고난 재능이 다릅니다. (킥루에서 선수 후보를 고르는 방식)
- 후보끼리 **능력치 합은 같고 구성만 다릅니다**. 어느 후보든 공정하게 시작합니다.

### 3-2. 능력치 (초안)

| 구분 | 항목 |
|---|---|
| 보이는 능력치 | 건강, 지능, 외모, 체력, 사회성, 행복, 돈 |
| 숨겨진 성향 | 끈기, 운, 재능 분야(공부·운동·예술·사업 등) |

- 숨겨진 성향은 처음엔 보이지 않고, 사건을 겪으며 조금씩 드러납니다.

### 3-3. 1년의 흐름
1. **올해의 활동** 고르기: 공부, 운동, 알바, 연애, 취미, 휴식 등 (나이에 따라 고를 수 있는 것이 바뀜)
2. 그 나이에 맞는 **사건 1~3개**가 선택지와 함께 등장
3. 연말에 능력치 변화와 **한 해 요약**을 보여 줌
4. 다음 해로

### 3-4. 인생 단계와 큰 사건

| 단계 | 나이(대략) | 큰 사건 예시 |
|---|---|---|
| 유년기 | 0~7 | 첫걸음, 유치원, 부모의 선택 |
| 학창 시절 | 8~18 | 성적, 친구, 학원, 동아리, 사춘기 |
| 진로 | 18~20 | 수능, 대학·취업·재수 |
| 군대 | 20~22 | 입대 여부, 보직 (성별·건강에 따라) |
| 청년기 | 22~35 | 취업·창업, 이직, 연애, 독립 |
| 장년기 | 35~60 | 결혼, 출산·육아, 내 집 마련, 승진, 중년 위기 |
| 노년기 | 60~ | 은퇴, 건강 관리, 손주, 노후 |

### 3-5. 인간관계
- 부모, 형제, 친구, 연인, 배우자, 자식이 **이름과 호감도**를 가집니다.
- 관계에 따라 등장하는 사건이 달라집니다. (예: 호감도가 높은 친구가 창업을 같이 하자고 함)

### 3-6. 사망과 평가
- 나이, 건강, 사고 확률로 사망합니다.
- 사망하면 다음을 보여 줍니다.
  - **인생 요약**: 연표와 주요 선택
  - **분야별 점수**: 행복, 재산, 명성, 인간관계 등
  - **인생 등급**과 새로 얻은 **업적**
- 역대 인생은 기기 안의 **명예의 전당**에 쌓입니다.

## 4. 사건 데이터 (초안)

사건은 코드와 분리된 데이터(JSON 또는 TS 객체)로 씁니다. 사건을 계속 추가해 나가는 것이 이 게임의 핵심 작업이기 때문입니다.

```ts
{
  id: "school_first_love",
  stage: "학창 시절",
  age: [14, 18],
  when: { 사회성: ">=40" },          // 등장 조건
  weight: 3,                          // 같은 조건의 사건끼리 등장 비율
  text: "같은 반 {이름}이(가) 자꾸 눈에 들어온다.",
  choices: [
    { text: "고백한다", effects: { 행복: "+5~-5" }, next: "..." },
    { text: "모른 척한다", effects: { 행복: -2 } }
  ]
}
```

- `{이름}` 같은 빈칸을 채워 **같은 사건도 매번 조금씩 다르게** 보이게 합니다.
- 한 번만 나오는 사건, 여러 번 나올 수 있는 사건을 구분합니다.

## 5. 기술 스택 (제안)

리듬게임과 같은 도구를 써서 익숙한 방식 그대로 갑니다.

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | TypeScript | 사건 데이터와 능력치 계산 실수를 줄여 줌 |
| 빌드 | Vite | 리듬게임과 같음. 같은 Wi-Fi에서 폰으로 바로 테스트 |
| 화면 | HTML/CSS (DOM) | 텍스트와 버튼 위주라 Canvas가 필요 없음 |
| 저장 | localStorage (MVP) | 진행 중인 인생, 명예의 전당. 데이터가 작아 충분하고, 커지면 IndexedDB로 옮김 |
| APK | Capacitor | 리듬게임과 **다른 앱 ID**로 따로 설치 |
| 테스트 | Vitest | 확률, 능력치 계산, 사건 조건 검사 |

## 6. 개발 단계 (초안)

### 1단계: MVP (핵심 재미 확인) — **만듦**
- 출생 후보 3명 고르기(능력치 합 같음) → 올해의 활동 → 사건과 선택지 → 연말 정산 → 사망 → 인생 평가
- 능력치 6개 + 숨겨진 성향 3개(재능·끈기·운, 겪으며 드러남), 활동 23개, 사건 59개
- 직업 8종(아르바이트, 중소기업, 대기업, 공무원, 전문직, 자영업, 예술가, 운동선수), 학력, 군대, 결혼·자녀·손주, 집, 은퇴와 연금
- 부모님과 주변 사람도 나이를 먹고 세상을 떠남
- 평가: 행복·인간관계·재산·수명·명성 → S~D 등급, 업적 16개, 명예의 전당
- 저장: 자동 저장, 저장 파일 내보내기/가져오기
- 자동 플레이 테스트: 무작위로 300번 살아 보며 수명(중간값 약 82세), 문장 오류, 등장하지 않는 사건을 검사

### 2단계: 인생다운 모양
- 인생 단계별 큰 사건, 인간관계, 직업, 결혼·자식
- 인생 등급, 업적, 명예의 전당

### 3단계: 오래 키우기
- 사건 계속 추가, APK 자동 빌드
- Gemini 옵션, 저장 파일 내보내기/가져오기

## 7. 개발 명령어

`life/` 폴더 안에서 실행합니다.

| 명령 | 하는 일 |
|---|---|
| `npm install` | 처음 한 번 |
| `npm run dev` | 개발 서버. 같은 Wi-Fi의 폰에서 표시된 주소로 접속 |
| `npm test` | 계산과 자동 플레이 테스트 |
| `npm run build` | 배포용 빌드 (`life/dist`) |
